# Triage

Triage files under `artifacts/tickets/`. Never access a third-party issue or pull-request service.

## Roles

Categories: `bug`, `enhancement`.

States: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`.

Each issue has exactly one category and one state. Use labels from `artifacts/config/triage-labels.md` when present; otherwise use the canonical names.

## Process

1. Scan `artifacts/tickets/` and show unlabeled, `needs-triage`, and newly updated `needs-info` issues.
2. Read the selected issue, prior notes, `artifacts/CONTEXT.md`, relevant ADRs, and `artifacts/out-of-scope/`.
3. Check for an existing implementation and verify the issue with focused tests or reproduction steps.
4. Ask only the questions needed to resolve ambiguity. Use `/grilling` and `/domain-modeling` when useful.
5. Update the issue file with the recommendation, evidence, state, and agent brief when ready.

Every appended triage note must begin with:

```markdown
> *This was generated by AI during triage.*
```

## Outcomes

- `ready-for-agent`: append an agent brief from `AGENT-BRIEF.md`.
- `ready-for-human`: append the brief and explain the required judgment.
- `needs-info`: append specific, actionable questions.
- `wontfix`: update the local state; record rejected enhancements under `artifacts/out-of-scope/`.

Do not delete issue history. Do not publish, comment, label, close, or synchronize anything outside this repository.
